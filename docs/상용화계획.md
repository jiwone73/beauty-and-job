# 상용화 계획

정리일 2026-10-04. 관리자 화면 「상용화 계획」과 같은 표다(원본은 lib/commercePlan.ts — 고치면 이 문서도 같이).

| 구분 | 항목 | 내용 | 상태 |
| --- | --- | --- | --- |
| 목적 | 이벤트 목적 | 오픈 초기에 기업·개인 회원 수와 사이트 트래픽을 최대한 모은다.<br>모든 기능을 무료로 열어 써 보게 하고, 그 동안 쌓인 활동 데이터로 유료화 기준을 만든다. |  |
|  | 노출 원칙 | 이벤트 기간 동안은 구매 등급이 아니라, 회원 수와 트래픽을 끌어내는 회원에게 노출 가산점을 준다. |  |
|  | 성공 판단 지표 | 가입 기업 수 · 승인 기업 수 · 이력서 등록 완료 개인 수 · 공고 등록 건수 · 입사지원 수 · 14일 활동 기업 수<br>목표 숫자는 오픈 후 첫 분포를 보고 정한다. | 미정 |

|  | 기업 체험 기간 | 승인일부터 3개월(승인 전에는 시작하지 않는다). 예: 10/20 승인 → 2027-01-19까지<br>가장 늦게 승인된 기업은 2027-03 말까지 이어진다(설정상 마지막 날 2027-03-30) |  |
|  | 개인 쿠폰 기간 | 10/12 ~ 12/30. 선착순 200명이 먼저 마감되면 그날 끝난다 |  |
|  | 전체 흐름 | 10/12 오픈, 데이터 쌓기 시작 → 활동 있는 기업이 쌓이면 가산점(3단계) 구현 시작(날짜가 아니라 기업 수 기준)<br>목표: 가입 기간이 끝나는 12/30 전에 가산점 규칙을 가동한다<br>체험이 끝나는 시점부터 유료화. 시기는 이벤트 결과를 보고 정한다 |  |
| 대상·혜택 | 기업회원 | 10/12 ~ 12/30 가입 후 승인받은 기업. 승인일부터 3개월 프리미엄 기능 전부 무료(공고 무제한, 인재 열람·제안·채팅, 인재 추천)<br>승인 전에는 시작하지 않는다. 끝나면 스타트(무료 회원)로 돌아가고 자동 결제는 없다<br>인재 연락처는 가입 승인을 받은 기업에게만 열린다 | 완료 |
|  | 개인회원 | 10/12 ~ 12/30 이력서 등록을 완료한 선착순 200명에게 메가커피 쿠폰 5,000원. 개인은 승인이 없고, 가입만으로는 지급하지 않는다 | 완료 |
|  | 가격 공개 | 이벤트 중에도 가격은 공개하고 카드에 「이벤트 무료 체험」을 붙인다. 구매 신청은 닫아 둔다(plan_sales) | 완료 |
| 노출 기준 | 지금 (1단계) | 메인 채용관: 이벤트 기업 공고를 먼저 등록한 순서로 프리미엄관 8곳·스탠다드관 25곳을 채우고, 같은 관 안은 최근 로그인 순<br>검색 목록: 등급 순, 같은 등급 안은 최근 로그인 순 | 완료 |
|  | 가산점 (3단계) | 순서는 자격 → 우선 기준 → 점수. 앞에서 갈리면 뒤는 보지 않는다<br>최근 14일 활동 기준. 매장/오피스는 구분 없이 합쳐서 줄을 세운다 | 구현 전 |
|  | 우선 기준 정의 | 점수보다 먼저 비교하는 항목. 값이 같으면 다음 우선 기준으로, 모두 같으면 점수로 가린다<br>숫자를 늘리는 쪽이 이기므로 항목마다 상한을 둔다(예: 14일에 공고 몇 건까지 인정). 상한 숫자는 분포를 본 뒤 정한다<br>기업 ① 공고 수 = 지금 진행 중인 공고 수<br>기업 ② 업데이트 빈도 = 최근 14일 안의 새 등록 + 재등록 + 수정 횟수. 업데이트하면 공고 날짜가 최신으로 바뀌므로 그 횟수를 센다. 같은 공고는 하루 1회까지만 센다<br>개인 ① 입사지원 = 최근 14일 안에 직접 낸 입사지원 수 ② 사진 공개 = 공개 여부 ③ 이력서 업데이트 = 최근 14일 안의 수정 횟수(하루 1회까지) | 구현 전 |
|  | 순위 예시 | A 기업은 진행 중 공고 3건·점수 40, B 기업은 2건·점수 90이면 A가 위다. 공고 수(우선 기준 ①)에서 이미 갈려 점수는 보지 않는다<br>공고 수가 같으면 업데이트 빈도(②)를 보고, 그것도 같을 때만 점수로 가린다 | 구현 전 |
|  | 점수 항목 뜻 | 기업 — 받은 지원: 내 공고에 들어온 입사지원 수 / 인재검색: 인재검색을 실행한 횟수 / 충실도: 매장정보·공고 칸을 빈칸 없이 채운 정도 / 제안 보냄: 인재에게 보낸 제안 수 / 로그인: 14일 중 접속한 날 수 / 공고 조회: 내 공고가 읽힌 횟수<br>개인 — 충실도: 이력서 칸을 빈칸 없이 채운 정도 / 로그인: 14일 중 접속한 날 수 / 이력서 조회됨: 기업이 내 이력서를 열어 본 횟수 | 구현 전 |
|  | 기업 기준 | 자격: 진행 중 공고가 있음<br>우선 기준: ① 공고 수 ② 업데이트 빈도<br>점수: 받은 지원 25 · 인재검색 20 · 충실도 20 · 제안 보냄 15 · 로그인 15 · 공고 조회 5 | 구현 전 |
|  | 개인 기준 | 자격: 이력서 등록<br>우선 기준: ① 입사지원(능동) ② 사진 공개 ③ 이력서 업데이트<br>점수: 충실도 50 · 로그인 40 · 이력서 조회됨 10<br>인재검색 정렬에만 쓰고 구직자 화면에는 보이지 않는다. 쿠폰 200명이 마감될 때 정렬에 켠다 | 구현 전 |
|  | 충실도·상한 | 충실도 = 공란 없이 다 채움(채운 칸 ÷ 전체 칸, 해당 없는 칸은 뺀다). 대상 칸은 구현 때 입력 화면에서 뽑아 확인받는다<br>항목별 상한(상한까지 하면 만점)은 분포를 본 뒤 정하고, 가중치는 설정 한 곳에 둔다 | 구현 전 |
|  | 공정성 | 공고 수정 점수는 공고당 하루 1회, 공고 건수는 진행 중인 서로 다른 공고만, 조회수는 낮은 가중치로 같은 사람의 반복 조회 제외, 로그인은 하루 1회<br>점수·순위·조회수는 관리자 화면에서만 보인다 | 구현 전 |
| 유입 분석 | 목적 | 이벤트 기간에 회원이 어떤 경로로 들어오는지 알아서, 어디에 홍보 시간과 비용을 쓸지 정하는 근거로 쓴다<br>가입한 뒤 실제 활동(이력서·공고·지원)으로 이어지는 경로가 어디인지도 본다 — 가입 수만 많은 경로는 성과가 아니다 |  |
|  | 지금 쌓이는 데이터 | 방문자의 첫 유입 채널(검색·SNS 등은 자동으로 가르고, UTM을 단 링크는 캠페인 이름으로 잡는다)<br>가입할 때 채널이 회원 정보에 남는다. 이 기능 이전 가입자는 「미확인」<br>관리자 「회원 유입채널」 화면: 채널별 방문자 · 가입 · 이력서 · 방문→가입 전환율 | 완료 |

|  | 채널 표시 규칙 | 홍보 수단(블로그·인스타·문자·제휴 등)마다 UTM을 단 서로 다른 링크를 쓴다. 링크를 하나로 쓰면 어디서 왔는지 갈리지 않는다<br>「미확인」 비율이 높으면 UTM 누락을 먼저 점검한다 | 오픈 후 |

|  | 활용 계획 | 가입도 많고 이어지는 활동도 많은 채널 → 힘을 더 쓴다(게시 빈도·예산 확대)<br>방문은 많은데 가입 전환이 낮은 채널 → 도착 화면과 가입 흐름을 점검한다<br>가입은 되는데 이력서·공고 등록으로 이어지지 않는 채널 → 안내를 보강하거나 그 채널을 줄인다<br>개인 쿠폰 200명이 어느 채널에서 채워졌는지 보고 개인 모집 채널을 정한다<br>유료화 후에는 가입 채널별로 구매 전환을 이어서 본다(어느 채널의 기업이 돈을 내는가) | 오픈 후 |
